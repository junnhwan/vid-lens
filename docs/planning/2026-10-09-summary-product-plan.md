## 1. 本轮要解决的问题

用户收藏了一个 B 站视频，希望迅速理解主要结论、必要过程和适用条件；遇到图表、代码、配置或操作界面时，还需要看到对应画面，并能回到原视频核查。当前摘要主要是纯文字，入口较深，导入后仍需要手动启动处理；字幕、摘要、画面、学习笔记导图与视频分类尚未连成这一条使用流程。

本轮产品主线是：**输入视频与可选处理要求，得到便于理解和回查的摘要；根据内容用文字、关键帧、图文和导图表达，并支持继续提问、修订和分类管理。**

摘要是主要交付物。Agent 的价值体现在判断哪些段落需要画面、调用工具找到合适画面、看过画面后补足说明，而不是让用户必须理解执行轨迹。是否优于现成工具，需要实际比较；本规划不把“使用了 Agent”视为产品优势的证据。

### 1.1 三项收益与对应证据

| 收益 | 用户感受到的变化 | 需要记录的证据 |
|---|---|---|
| 少操作 | 一次导入即可启动摘要，离开页面仍继续处理 | 必要点击数、手工操作数、首次可读与完整完成耗时、失败恢复步骤 |
| 少漏信息 | 摘要保留关键结论、过程、条件，画面补上字幕没说明的信息 | 同视频原片审核、关键点清单、图文相关性与错误记录 |
| 容易回查 | 章节与截图带真实来源位置，点击能看对应片段 | 来源身份与分 P 一致性、时间来源、实际点击回放结果 |

这些是待测目标，没有当前提升百分比或生产效果结论。摘要质量、速度、成本分别报告，避免用更多截图或更多模型调用代替质量。

## 2. 范围与默认决策

### 2.1 本轮范围

- B 站普通视频链接，包括明确选择的分 P；`b23.tv` 短链需要安全解析到同一来源身份。
- 保留本地视频上传和 ASR；本轮不增加 YouTube 能力，也不顺带删除已有兼容代码。
- 获取合适的 B 站字幕后跳过 ASR；不可用时按可用能力降级到 ASR。
- 统一文字来源、章节正文、来源时间、截图引用和导图的内容契约。
- Agent 按需截图、图注、回放，支持纯文字结果与补图失败降级。
- 摘要支持文字、关键帧和图文表达，导图作为可选视图；用户要求影响重点与形式。
- 导入、视频库、详情页三处围绕摘要重排，复用已有播放器、修订和任务状态能力。
- 桌面 Web 的摘要、问答分别提供专注视图；摘要生成、回答流式输出和明确修订均展示按实际活动动态出现的短标题与可展开记录，保留轻微呼吸和真实完成反馈。
- Agent 自动生成/复用领域标签、去重，用户可管理别名和合并；视频库支持分类筛选。
- 问答页可展开摘要、选择段落或文字作为注释，与用户问题一起发送；保持历史上下文。
- 已有 Markdown 摘要、修订、预览、应用、撤销、导出和术语规则保持可用。

### 2.2 本轮不扩展的范围

深层分类树、跨平台接入、付费与团队协作、公开分享、自动发布、整站设计系统替换、视频剪辑、自动生成课件、全视频逐帧理解、所有字幕缺口的局部 ASR 补齐、手机布局改造，以及强制把 RAG 放进摘要流程。这些不作为完成本轮的前置条件。

### 2.3 已确定的默认值

| 决策 | 第一版选择 | 原因 |
|---|---|---|
| 导入主动作 | 前端显式提交“导入并生成摘要”；高级选项可选“仅导入” | 缩短主流程，保留原有导入用途 |
| 服务端旧调用 | 未传自动摘要意图仍保持旧行为 | 避免历史客户端无意产生模型调用 |
| 执行顺序 | 先确认来源身份并完成媒体下载，再探测字幕并选择文字来源，随后派发独立摘要任务 | 缩小首轮改动；本轮不承诺字幕先于媒体下载完成 |
| 文字选择 | 匹配语言的已确认上传者字幕 → 可用平台自动字幕 → 类型未知但可用的字幕 → ASR | 来源类型只有确证时才标明；质量检查仍是必要条件 |
| 字幕语义 | “平台字幕”表示来源，不能统称为人工校对或更准确 | 平台字幕也可能识别错误、截断或时间漂移 |
| 分 P | 未指定时为第一 P；指定 `p` 时只处理该 P | 禁止文字来自一 P、媒体和截图来自另一 P |
| 生成方式 | 上下文足够用一次摘要请求，超出才复用分段与恢复机制 | 保留现有上下文预算判断，避免无必要拆分 |
| 图文模式 | 新入口清楚展示“按需补充画面”选项；能力允许且用户选择开启时执行 | 尊重已有视觉关闭设置；缺 Vision 仍能获得文字摘要 |
| 摘要形式 | 默认自动选择合适表达；高级选项可偏好文字、图文或关键帧 | 形式服务内容，不需要用户先理解新的成果类型 |
| 展示顺序 | 短概览 → 标签 → 可展开导图/目录 → 章节图文摘要 | 结论先可读，导图默认提供紧凑章节概览，完整导图按需展开/放大 |
| 进度 | 文字/图文模式先发布可读文字；关键帧模式等待实际选图，失败可明确降级 | 不把无图结果冒充完成了关键帧摘要 |
| 标签 | 自动分类默认开启，生成少量领域标签，优先复用已有词表；用户可关闭 | 分类自动完成，人工决定始终优先 |
| 标签合并 | 名称归一/明确别名自动去重；未被用户维护的 Agent 标签可有依据地合并；人工标签的语义合并需确认 | “数据库”和“PostgreSQL”等层次不同的词保留各自含义 |
| 多标签筛选 | 默认 AND，用户显式切换 ANY 时使用 OR | 组合标签可以缩小目标视频集合 |

字幕类型相同的多个候选，按语言偏好、可用性和稳定的候选排序选择，不能仅按字幕条数挑选。无合适字幕时展示原因；缺 ASR 配置则保持媒体可用，并让用户配置后继续，不无限等待。

### 2.4 摘要形式是同一份内容的不同表达

| 形式 | 用户看到的内容 | 生成要求 |
|---|---|---|
| 文字 | 概览与段落/章节 | 没有视觉收益时可没有图 |
| 关键帧 | 几张重要的视频截图，附必要图注和回放时间 | Agent 实际检查并挑选；正文可很少或为空，不是随机抽帧 |
| 图文 | 正文与解释相关内容的截图 | 图片靠近对应段落，并参与完善说明 |
| 导图 | 章节、概念和关系的概览，可定位正文/画面 | Agent 在摘要中组织层级，视图由该结构派生 |

默认自动模式根据视频内容与用户要求决定表达，用户也可选择偏好。第一批先完成文字基础，第二批补齐关键帧/图文/导图；不能把暂时未接入的形式显示为已支持。导图可以和前三种形式组合，不设四套独立生成、版本与编辑流程。

字幕选择是输入质量与成本策略，不承担产品名称。Agent 生成导图需要理解内容和组织概念；渲染仍使用同一份摘要结构，避免修改正文后导图变成另一份说法。

## 3. 当前能力与真实缺口

以下是本次源码核查结论，不代表已完成线上验证。

| 项目 | 当前可复用能力 | 本轮需要补齐 |
|---|---|---|
| 链接导入 | yt-dlp 下载、下载作业租约、媒体存储、去重 | B 站字幕探测；保留并解析分 P；完成下载后自动推进 |
| 文字来源 | ASR 全文、分片、时间映射及现有来源冻结 | 来源类型、字幕 cue、可用性判断；统一读取与安全缓存 |
| 摘要 | 独立 summary 作业、上下文预算、分段检查点 | 结构化图文文档、真实 cue 引用、渐进发布和关联补图 |
| 视觉 | 按需视觉调查、画面提取、预算与观察记录 | 摘要作用域接入、质量选择、观察截图的授权读取 |
| 修订 | 用户级摘要版本、AI 修改、预览/应用/撤销、术语规则与操作状态轮询 | 原子维护文档与 Markdown；接入修订活动事件，不能把操作状态当成已有细粒度执行流 |
| 导图 | 学习笔记的 Markmap 展示与节点选择 | 从摘要章节派生，复用渲染层而不复用另一份笔记内容 |
| 标签 | Markdown 中的领域标签解析展示 | 用户实体、自动创建/复用、别名/合并、拒绝记录、管理及筛选 |
| 界面 | React Router + Vite、视频库、详情、播放器、摘要弹窗 | 摘要详情主视图、导入自动意图、卡片主动作与筛选 |
| 问答衔接 | 学习笔记整块提问入口；Chat 已有 progress、step 与工具事件、ThinkingProcess 时间线 | 摘要选段与上下文快照；将公开动作说明扩展成短标题，复用事件归并，不另造问答流程 |
| Agent 活动展示 | Planner 的 public_summary、实际工具生命周期、运行/步骤日志及已有公开进度 | 拟增 public_title 与统一活动投影；摘要生成和修订尚无本文要求的实时活动流，需按 S2/S3/S5A 接入 |
| 知识库 | 已有多视频授权范围、向量/BM25 混合召回与融合 | 后续接入标签筛选与按上下文预算选择全文/检索；不再造检索器 |

特别注意：当前 URL 清洗会丢掉 B 站 `p` 参数；URL 导入开始时的 `FileMD5` 是 URL 的临时摘要，下载后才成为媒体 MD5；当前摘要缓存主要按媒体 MD5 复用。这三点不能直接用于新的字幕身份、摘要来源和跨用户分类。

本机此前核查 yt-dlp `2026.08.19` 的 B 站提取器可获取平台暴露的字幕轨道；弹幕 XML 也可能出现在字幕集合中，必须排除。`subtitles` 字段不能证明字幕由人上传。该核查没有证明真实 B 站链接已成功下载，运行时登录、风控、网络和具体视频仍需验证。

## 4. 端到端用户流程

### 4.1 首次导入

1. 用户粘贴 B 站链接，确认选中的分 P；默认选择导入并生成摘要，可填写关注点和形式偏好。
2. 服务端持久化导入意图，检查归属、URL、能力和幂等；返回任务位置。
3. 下载选定媒体，记录 BV/aid/cid/part 与媒体修订，不能用 URL 临时 MD5 当内容身份。
4. 探测字幕，排除弹幕，检查语言、时间和明显异常。合适字幕成为不可变文字来源；否则使用 ASR。
5. 来源发布和摘要待执行意图一起持久化；摘要不等待 RAG、Embedding 或全量视觉索引。
6. 生成并校验摘要结构。文字/图文模式先发布可读文字；关键帧模式先准备候选计划。
7. 需要画面时，Agent 调查并查看候选，选出重要截图；按模式发布关键帧或图文版本，导图从同一结构派生。
8. 根据内容自动创建或复用少量领域标签、去重。标签失败不影响摘要可读。
9. 用户按标签找视频、阅读和回放；可以选中摘要内容继续提问，或明确要求 Agent 修订。

浏览器不是编排器。用户关闭详情页不取消已接受的服务端作业；上传中的文件仍遵循已有上传取消规则。

### 4.2 重复导入、重新生成和用户修改

已有可用摘要且来源、配置与生成选项一致时，优先阅读结果，不自动重复收费调用。重新生成是明确操作，旧版本在新结果发布前继续可读。

用户修改正文或标签后，后台结果不得覆盖人工决定。摘要修订继续沿用现有版本冲突与保留/使用新原稿流程；补图任务必须绑定生成版本和文字来源。用户删除的标签保留拒绝决定，后续重生成不反复添加。

### 4.3 失败与降级

| 情况 | 用户看到的结果 | 可继续的动作 |
|---|---|---|
| 无字幕、只有弹幕或只有烧录字幕 | 已保存媒体，转为 ASR；缺 ASR 时说明配置缺失 | 配置后继续或阅读已有结果 |
| 字幕接口需登录、风控或暂时失败 | 明确该来源未取得；有界重试后可走 ASR | 重试字幕、使用 ASR；不把错误当作“视频无字幕” |
| 摘要模型失败 | 旧摘要保持可读，或显示无摘要及错误原因 | 只重试摘要，不重复下载和识别 |
| 缺 Vision、画面无帮助或补图失败 | 完整文字摘要；说明画面未补充的原因 | 继续阅读或稍后补图 |
| 图片读取失败、导图布局失败 | 正文保留；图注/时间或文字目录继续工作 | 重试局部资源 |
| 新来源与用户版本冲突 | 用户当前版本继续展示，并提示存在新生成版本 | 预览后选择保留或采用 |
| 选段后摘要发生变化 | 保留问题草稿，提示重新选段或使用可验证的保存版本 | 不静默换成新正文 |

## 5. 摘要内容质量

### 5.1 正文标准

短概览回答“讲了什么、主要结论是什么、适合在什么情况下使用”。章节正文保留关键论点、必要推导/步骤、假设、限制及重要反例，减少逐句复述。内容无法确认时注明未知，不靠补图或语言润色填出不存在的事实。

摘要、目录和导图消费同一份当前有效内容。章节有稳定 ID、标题、正文、来源引用和图片引用。标题修改不改变 ID；删除章节要同时处理其图片和导图选择状态。旧 Markdown 摘要继续阅读，不能为打开页面自动调用模型迁移。

### 5.2 配图标准

适合配图的例子：字幕说“参数这样填”而界面显示具体值；讲解依赖一张架构图；代码中的关键条件没有被读出来。仅有人说话、画面不提供额外信息时，可以没有截图。

每张图都必须与相邻正文有明确关系，保留截图时间、图注与来源媒体修订。Agent 必须实际看过候选图，才能写“根据画面发现”的内容。模糊、重复、无关、预算不足时不选图。模型自行给出的图片 URL、文件路径或不存在的截图引用不能发布。

默认全篇预算见实现指南；数量与耗时是工程限制，不是质量目标。允许先文字后图片；补图过程的内部轨迹放在按需展开的运行详情。
生成期间默认可见当前动作和少量近期记录；完整轨迹仍按需展开，具体体验见 7.2。

### 5.3 导图标准

短概览后提供可展开导图。Agent 可以组织章节、关键概念和层级并写入同一摘要；导图读取这份结构，点击节点定位正文或画面。修订层级和正文后同步更新；不要另存一份无来源关系的导图内容。需要修正概念结构时可运行明确的摘要结构修订，不必禁止所有针对结构的 Agent 调用。长图折叠，桌面可放大查看；导图默认不占据整屏。

### 5.4 与现有“成果”的关系

摘要是视频的主要产出，内容结构自然会接近已有成果的块、版本、来源和多视图能力。优先复用阅读、块选择、导图、修订预览和 Agent 执行组件，保留摘要当前资源及版本体系作为唯一权威。

第一版不强制将摘要存成学习笔记，也不把同一正文同时维护在 SummaryRevision 和 ArtifactVersion 两处。现有成果 schema 限定 study，需适配后才能复用；不能直接声称已有支持。统一成果列表可后续用只读投影展示摘要，页面首先让用户直接阅读。

### 5.5 按用户要求修订

保留并前置现有 Agent 摘要修订：用户可改全文或选块的重点、表达、结构和图注，先预览再应用，支持撤销。应用后正文、图片关联、导图与导出保持同版本；事实修订仍要回到真实来源核实。普通提问不会修改摘要，明确点击“让 Agent 修改”才提交编辑请求。

## 6. 标签成为视频库的正式数据

第一版平铺标签，用户能创建、改名、登记别名、合并、添加到视频和从视频移除。自动分类默认创建/复用当前用户的少量领域标签，每次最多自动处理 5 个、每个视频最多 20 个有效标签；这些上限是可调整的初始工程配置。无法确定类别或含义时保留建议，不强行添加。

规范化包括 NFKC、去掉首尾空白、折叠连续空白和 Unicode 大小写折叠，保留 `C++`、`C#`、`.NET` 等标点。规范名和别名共用唯一命名空间。明确别名自动归一；Agent 优先从已有词表选 ID，再考虑新词。自动维护且未被用户修改/人工使用的重复标签，可按等价依据合并；语义不确定、人工维护或上下位关系的词形成合并建议。用户改名可保留旧名为别名，冲突时整体回滚。

人工标签优先，Agent 只能维护自己添加的关系。“待读”等个人意图标签由用户选择。删除或拒绝自动标签会形成持久拒绝记录；用户主动恢复后才重新允许。标签、候选与计数按账号隔离，不随媒体 MD5 跨用户共享。

视频库关键词、状态、标签条件在服务端组合；多标签默认 AND，可切换 OR。分页与总数作用于全库，不在当前页前端过滤。筛选状态放入页面 URL，返回和刷新后保留。

同一套标签后续可以筛选知识库内视频，但不会自动把视频加入知识库或改变权限。小规模内容在完整来源能装进模型上下文时可全文问答，规模/成本超出预算时才按需使用已有混合检索。这个择路目前尚未完整实现，作为 S5B 后续工作；摘要生成不依赖它。

## 7. 页面调整

| 页面 | 主要交付 | 交互与异常要求 |
|---|---|---|
| 导入弹窗 | 明确“导入并生成摘要”与可选补图；返回任务详情 | 上传与处理分开；去重命中直接阅读；配置缺失只阻止相关阶段 |
| 视频库 | 卡片主动作是阅读/生成摘要，展示短预览、少量标签和摘要进度 | 预览取有效用户版本；标签全库筛选；空库与无结果不同 |
| 视频详情 | 摘要成为默认正文，概览、标签、导图、图文章节直接可读；S5A 接入可展开侧栏问答 | 正文主栏，右侧同一辅助区切换播放器/问答；S5A 前问答沿用现有入口 |
| 次级入口 | 字幕、问答、笔记、索引、画面集合、运行详情 | 沿用现有路由和能力；局部失败不阻止正文 |
| 标签管理 | 从视频库和详情进入轻量管理面板 | 合并显示影响与冲突；不用新增深层分类页面 |
| 问答页 | 可折叠摘要面板，选段作为注释卡片，问题单独输入 | 选择后不自动发送；保留草稿；能移除、展开与回到原段 |

键盘能访问目录、节点与回放入口；图片有说明文本；播放跳转后焦点可预期。摘要、图片、导图和播放器独立加载；无时间信息时不显示虚假的可跳转时间。

摘要选段是衍生内容，不自动成为视频原话。发送前校验所属视频、版本和选段，接受后保存实际上下文快照，历史消息不随着摘要重写而改变。先支持单一章节内选择和整段选入，不要求实现复杂跨章节划词。

### 7.1 深色主题与专注视图

摘要、现有成果、导图和问答沿用统一暖炭色主题。深色模式下阅读面、导图画布和图注面使用主题变量，层级由底色差、细边框、字号与留白建立；原视频画面保留自身颜色。已有显式浅色主题继续按主题变量适配。

| 视图 | 页面安排 | 进入与退出 |
|---|---|---|
| 默认工作区 | 摘要主栏，右侧同一辅助区切换原视频与问答；辅助区可收起 | 阅读、回放、选段提问可在同一工作区完成 |
| 摘要专注 | 摘要占据工作区，正文保持舒适行宽；图片与导图获得更大空间 | 标题栏“放大阅读”；“恢复布局”或 Esc 返回 |
| 问答专注 | 会话占据工作区，输入框、选段注释和消息更宽；摘要可按需打开 | 标题栏“放大问答”；“恢复布局”或 Esc 返回 |

放大是扩大可用区域，不只是放大字体或图片。先实现页面内专注模式，无需浏览器原生全屏；复杂拖拽分栏后置。切换保留两侧滚动位置、输入草稿、选段与版本、播放器时间和运行状态，不重发请求、不重新生成摘要。宽屏正文仍有行宽上限；本轮仅验收桌面 Web，参考 1440px 与 1024px 宽度。窄桌面默认收起辅助区，需要时再打开。嵌套图片预览或弹窗优先处理自己的 Esc。

最终工作区在视频详情内提供侧栏问答和两种专注视图，S2 先摘要阅读，S5A 再接入问答。独立问答路由保留并复用同一会话能力；跨路由按账号/视频/会话保存视图草稿与注释，不能仅依赖组件本地状态。退出账号或切换账号时清理对应临时状态。

### 7.2 随实际活动更新的 Agent 运行过程

这部分展示 Agent 此刻实际在做什么。摘要生成、问答与摘要修订共用展示规则，每次操作有独立运行身份；步骤由真实活动事件逐条加入，不预先摆出“理解 → 检索 → 截图 → 回答”等待办清单。系统下载、获取文字等准备动作可以有固定名称，但只有对应执行开始时才出现。

Agent 决定下一步时可随同决策给出 `public_title`，例如“核对连接池的最大连接数”，服务端限制长度并确认它与实际动作相符；缺少合适标题时按工具与安全参数映射成“检索相关字幕”“查看 06:12 附近画面”。现有 `public_summary` 可作为按需展开的公开说明。标题描述行动目的，不能先写“已经验证正确”；完成、失败和重试必须由真实执行结果决定。不得每隔几秒额外调用模型编写状态文案，也不把供应商 reasoning 或内部思考草稿直接作为活动标题。

例如一轮问答可能依次出现：

- 找到连接池参数相关字幕（完成）。
- 查看 06:12 的配置画面（完成）。
- 核对客户端连接数与池大小（执行中）。

如果这轮不需要画面，不出现截图步骤；证据不足时可追加新的取证动作；工具失败时保留失败记录，重试有自己的尝试身份。相同工具在不同时间窗执行是不同活动，不能按工具名称合并成一条。

默认紧凑显示当前活动与最近 3 条记录，完整历史按需展开。当前一条有轻微呼吸标记，活动进入与完成提供短反馈；实际选帧事件可附授权缩略图及时间。用户看正文或历史消息时不强制滚动，手动收起后不反复打开。系统长时间没有新活动时保留最后已知动作并显示耗时/连接状态，不用“分析中”“继续分析”轮播填补等待。

摘要文字发布后立即开放阅读；只有仍在补图时显示“文字摘要已就绪，正在补充画面”，下方继续更新实际活动。问答的回答增量与活动事件独立到达，正文已开始输出后过程仍可见并继续更新；文字结束也不意味着引用保存或整个运行已经完成。修订的活动区域归属当前修订操作，预览就绪与应用完成分开，等待用户应用时停止执行动效，不把旧摘要版本提前替换。

排队、执行、连接中断、完成、失败、取消分别呈现。连接状态与服务端运行状态独立；恢复以运行快照/事件游标重建并去重，迟到的 running 事件不能把已完成活动改回执行中，旧运行不能回填新运行。具体拟扩展契约与现有 Chat 适配见[实现指南 4.2.1/4.2.2](2026-10-09-summary-implementation-guide.md#421-动态活动的公开契约)。摘要生成和修订尚未接入该细粒度实时展示流，不能仅凭本地原型声称生产已支持。

只在有真实总量时显示进度比例，未知总量用活动与数量。呼吸仅表示活跃执行，完成/失败/取消或连接中断后停止；减少动态效果时保留文字与图标。可重放的原型序列只是模拟事件，服务端接入后事件由运行事实产生。

## 8. 实施顺序与工作包

| 工作包 | 交付内容 | 依赖 | 可以验收的结果 |
|---|---|---|---|
| M0 | 再核查源码/WIP、固定契约和测试样本 | 无 | 当前与拟新增行为清单、工作区保护、明确完成范围 |
| S0 | 文字来源与摘要文档结构、版本/兼容基础 | M0 | JSON/Markdown 同版本；旧摘要和修订仍能读写 |
| S1 | B 站身份与字幕优先、自动持久推进 | S0 | 正确分 P；有效字幕 ASR 调用为 0；失败可恢复 |
| S2 | 结构化文字摘要、入口前置、专注阅读与统一活动投影基础 | S0、S1 | 一次导入拿到可读摘要，不依赖索引；放大/恢复不丢状态；已有真实活动可动态呈现；旧版本保留 |
| S3 | 摘要 Agent 按需补图、关键帧/图文、授权图片/导图与可恢复活动流 | S2 | 同一内容多种表达，画面必要且真实，回放正确 |
| S4 | 自动领域分类、用户管理与视频库筛选 | S2；可与 S3 并行 | 自动去重、人工决定保留，筛选分页正确 |
| S5A | 摘要选段问答、共用侧栏/专注、上下文快照、选块修订与动态活动 | S2；图片选择可后续扩展 | 选段+问题可发送；流式回答期间过程持续更新；修订真实活动与预览/应用分离 |
| S5B | 后续知识库标签过滤、全文/混合检索择路 | S4、统一来源；可后置 | 授权成员一致，全文不截断伪装，复用现有检索 |
| S6 | 真实链路验证、质量对照、阶段交付 | S3、S4、S5A | 摘要主流程完整，证据与限制报告；S5B 单独验收 |

面向用户分三批交付：第一批 S0–S2；第二批 S3；第三批 S4、S5A、S6。S5B 是后续知识库增强，独立安排，不拖住摘要体验。标签后端可并行，每批通过相关检查后再拓展下一批。

业务工作包状态：M0/S0/S1/S2/S3/S4/S5A/S5B/S6 均待实施/核验。公开桌面原型已用于交互演示；文档和模拟原型不构成上述生产功能完成证据。

## 9. 验收与产品比较

### 9.1 必须满足的工程条件

- 正确的 BV/cid/分 P 与媒体修订贯穿字幕、摘要、截图和回放。
- 有可用字幕时不调用 ASR；弹幕不被当成字幕；来源类型未知时不标人工。
- 任务接受后可恢复，重复投递不重复发布，旧 lease 不得覆盖新结果。
- 已发布文字不依赖补图、标签或索引成功；重新生成不先删除可读版本。
- 有效文档、Markdown 投影、目录与导图一致；预览/应用/撤销覆盖结构化文档。
- 用户修改、拒绝标签和视频归属在后台任务、缓存、图片读取与导出中持续生效。
- 时间未知时诚实显示未知；截图引用必须真实存在且属于同一来源。
- 文字/关键帧/图文与导图对应同一有效版本，形式偏好与实际降级可见。
- 选段上下文与问题分开，发送前验证、历史快照稳定；普通问答不自动修订。
- 自动分类不覆盖用户标签/拒绝；后续检索只在授权知识库/视频范围内过滤。
- 摘要/问答放大与恢复不丢草稿、选段、滚动和播放位置；各视图遵循同一主题。
- 摘要生成、问答、修订的活动短标题按真实动作逐条出现；无预设等待清单、无假活动轮播。
- 标题可来自 Planner 的 public_title 或工具映射，状态来自真实生命周期；回答增量不阻断活动更新，等待应用不是执行中。
- 记录按运行/活动/尝试/游标归并，恢复不重复、迟到不倒退；终态停止动效，减少动态效果仍可理解状态。

### 9.2 样本与比较方法

准备一组固定 B 站样本：有上传者字幕、有自动/未知字幕、无字幕/只有弹幕、分 P、长视频、代码/配置演示、图表讲解、纯讲述，以及需要登录或接口失败的案例。自动测试用可公开的自造 fixture；真实视频和审核记录放在忽略目录。

质量比较先用同一字幕与同一模型比较“全文 + 合适提示词”和新摘要；图文增益再与相同文字结果比较。若比较其他工具或直接视频多模态模型，记录它们实际输入、模型、可用性和成本，不能把不同输入造成的差异全归因于 Agent。

人工依据原视频检查关键点遗漏、编造、条件误读、图文不对应及回放错误。未审核字段保持未审核；模型评分只能辅助。首轮样本规模用于发现问题，不宣称统计显著的市场优势。

记录字幕命中/降级原因、阶段耗时、首次可读耗时、工具/模型调用、tokens/费用来源、截图选中与丢弃理由。供应商未返回费用或 usage 时标为未知或估算；字幕跳过 ASR可以降低识别成本，但下载仍有耗时。

### 9.3 真实链路的完成边界

源码检查、fixture 单测、PostgreSQL 集成、浏览器交互、真实 B 站来源验证和人工质量审核分别报告。完成模拟用例不能写成真实导入成功；本地成功不能写成已部署；提交、推送和发布需另有用户授权。

## 10. 风险与降级边界

| 风险 | 本轮处理 |
|---|---|
| 字幕接口、登录和风控变化 | 有界超时/重试、原因码、ASR 回退；记录实际 yt-dlp 版本 |
| 字幕存在但错误/截断 | 轻量质量检查和来源标记；不自动声明比 ASR 更准 |
| 截图与正文错配 | 真实 cue 定位、实际看图、稳定块引用、媒体修订校验、人工审核 |
| 旧 Markdown 与新文档并存 | 新结构为权威、Markdown 为投影；旧路径按版本适配，避免双写漂移 |
| 自动补图撞上人工修订 | 绑定版本 CAS，保留人工版本并走已有冲突决策 |
| 字幕和用户偏好污染缓存 | 新摘要缓存纳入来源/配方/配置/偏好；第一版新结果按用户任务隔离 |
| 标签迅速膨胀 | 复用词表、少量自动创建、来源标记、等价归并、用户保护与上限 |
| 额外视觉成本与延迟 | 全篇共享预算、先文字后图、能力关闭/无帮助时跳过 |

外部下载器目前的 URL 预检查不是完整网络沙箱。本轮要补足分 P、短链、字幕 URL 与重定向的验证及测试；如果部署网络层仍未限制外部进程的后续访问，必须记录这个剩余边界，不能仅凭 DNS 预检查宣称已彻底防止 SSRF。

## 11. 开新 Agent 会话的交接方式

先读本文件确定范围，再按[实现指南](2026-10-09-summary-implementation-guide.md)执行 M0 和 S0–S2。首个新会话交付第一批基础链路；第二个会话交付关键帧/图文与导图；第三个会话完成自动分类、摘要问答衔接及综合验收。后续另行安排知识库择路。会话边界不能代替工作包验收，接手时检查实际代码和证据。

实现指南末尾有可直接复制的启动提示和交接模板。规划与实现指南位于公开的 `docs/planning/`，前端交接位于 `docs/design/`，原型位于 `docs/prototypes/summary-experience-desktop-v2/`。新会话从仓库读取这些文件，并核对工作包状态和实际实现。
