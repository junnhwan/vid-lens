## 1. 目标与参考顺序

用户输入视频及可选关注点，一次操作后获得易读、可回查的摘要；Agent 按内容选择画面、组织导图与标签，用户可继续选段提问或明确修订。原型验证摘要阅读、问答与生成过程的完整使用效果。

参考顺序：最新交互要求 → 当前源码 → 产品规划与实现指南 → 现有原型视觉。仅做桌面 Web，本轮不增加手机布局与手机验收。

## 2. 交付边界

公开文件位于 `docs/prototypes/summary-experience-desktop-v2/`，包括真实 DOM 构建的 `index.html`、本地 CSS/JS、示意 SVG 和说明。数据、运行事件、回答与修订来自本地 fixture；界面保留轻量“原型 · 模拟数据”说明。原视频截图用本地示意素材，不将私有视频、凭据、签名 URL 或内部路径放入公开文件。

原型和公开规划用于交互评审，原版保留，业务前后端、数据库、依赖与锁文件不在原型实施范围。正式业务接入按实现指南另行实施。无需收费模型、真实 B 站下载或真实用户会话。

原型 README 写明打开方式、可重放状态、已做的浏览器检查与未来接点。模拟通过只说明交互可运行，不证明真实 Agent 成功、字幕质量、生产性能或已部署。

## 3. 页面与视觉

保留“映知 / VIDLENS”品牌和暖炭/琥珀配色。摘要、成果阅读面、导图、图注与问答使用统一深色表面，靠底色差、细线、字号和留白区分层级；视频画面保留自身颜色。正式接入复用主题 token，已有显式浅色主题另按业务兼容检查。

桌面默认摘要主栏，右侧同一个辅助区在回放与问答间切换。标题和主操作紧凑，BV/导入时间/文字来源等细节按需展开；概览、标签、章节概览与图文正文形成连续阅读流，不堆成多层大卡片。

导图默认显示紧凑章节概览，完整树按需展开，支持大尺寸深色对话框；节点跳回相应正文。视频库只保留一个主导入入口，默认展示最多 6 个常用标签，并始终保留已选标签；“全部标签”可搜索名称/别名与多选，筛选结果与所选条件一致。

验收 1440px 宽屏与 1024px 窄桌面。窄桌面可收窄导航并默认收起辅助区，需要时打开问答；输入框始终在可视区。宽屏正文也有舒适行宽上限，避免为了填满屏幕把文字拉得过长。不要为手机新增页面结构。

## 4. 摘要与问答均可放大

提供“放大阅读”和“放大问答”，以页面内专注模式让目标面板获得更大空间，并有“恢复布局”和 Esc 返回。嵌套图片预览/修订等浮层优先处理自己的 Esc。

- 摘要专注：正文保持行宽上限，图片与导图可用更大空间；提问和回放仍可按需打开。
- 问答专注：会话、输入框、选段注释更宽；退出返回原布局。
- 两种专注互斥，可直接切换；不需要浏览器 Fullscreen API 或复杂拖拽分栏。
- 放大/恢复保留各自滚动锚点、草稿、引用版本、播放器时间、活动记录和正在进行的模拟输出；不重复提交。
- 按钮有可读名称，键盘可操作；退出后恢复可预期的焦点。

## 5. 动态 Agent 活动，而非固定步骤清单

### 5.1 核心规则

三类运行共用 `ActivityView`：摘要生成、单轮问答、明确摘要修订。每类活动归属自己的 run 与主体，不能互相覆盖。初始只有“等待开始”或真实已发生的活动；未来步骤不提前列出，不以固定 workflow 的 pending 清单填满卡片。

每次模拟动作开始时追加一条短标题；真实模拟结果到达时更新该条的 done/error/cancelled，重试有独立 attempt。具体做几步、是否查看画面、是否追加检索取决于本轮 fixture 的实际分支。没有调用截图工具就没有截图标题；同一工具检查两个窗口是两个活动，不能按名称去重。

例如问“连接池配置是否适合高并发”可能出现：

1. “检索连接池参数相关字幕”开始并完成。
2. “查看 06:12 附近的配置画面”在工具实际模拟执行时才出现。
3. “核对连接数与池大小”在对应核对动作开始时出现。
4. “整理配置建议”与回答文字流式输出同时可见，随后有实际的保存/引用确认。

另一问题可能只读取已有文字并回答；用户修改术语可能只调用一次修订 planner 和校验。不能为统一视觉强制凑出以上四步。活动标题表示动作目的，不在动作开始时提前声称已找到/已核实。完成勾选由执行结果决定。

### 5.2 标题与事件来源

本地 `activity.js`/`activity.css` 提供共享活动状态与展示；`core.js` 的摘要模拟运行、`views.js` 的问答和修订动作发出事件。原型计时器用于重放本地 fixture 的事件，不是生产状态生成方式。空等一段时间不能自动新增“继续分析”等假活动。

正式接入时 Planner 在原有决策中同时给出拟新增 `public_title`，`public_summary` 作为安全公开 detail；缺失/过长/不符时按实际工具映射回退。当前 public_summary 已存在，public_title 尚未落地。工具生命周期决定开始/完成/失败，不能让模型凭文案声明完成。无需每隔一秒额外调用模型总结，也不从供应商 reasoning 或内部草稿截取标题。

语义契约按[实现指南 4.2.1](../planning/2026-10-09-summary-implementation-guide.md#421-动态活动的公开契约)：run_id、subject、activity_id、attempt、seq、state、title、可选 detail/tool/time/references。生产适配优先沿用 Chat 的 label/progress/step 与运行快照字段；本地 fixture 可用简化同义字段，不要求新建独立执行数据库。

### 5.3 展示与输出并行

默认紧凑显示当前活动和最近 3 条，完整历史可展开；手动折叠决定保持。只给当前活跃活动一个小型呼吸标记，不让多行同时闪动。新行短暂柔和出现，完成变勾。实际选帧后可附授权缩略图、时间与回放入口。

摘要生成先开放已发布的完整可读文字，补图活动仍更新；没有画面收益或补图失败时保留文字并说明。问答的文本增量与活动事件独立处理：开始回答后过程仍可见，后续整理、保存等动作可继续出现，直到实际 run 终态。既有正文不被活动更新清空，用户阅读历史时不强制滚到底。

修订活动归属当前编辑操作，完成生成后显示差异预览；等待应用时停止呼吸，应用后才更改版本。普通提问不改摘要。只有工具实际执行时才能显示“定位画面”“核对字幕”等动作；简单措辞调整可以没有这些步骤。

### 5.4 连接、恢复与终态

运行状态与浏览器连接状态独立。断线显示“连接中断，等待恢复状态”，暂停活跃动效，不把后端任务改成失败；重连通过快照与连续确认游标恢复。按 run/activity/attempt/seq 幂等归并，重复不添行，迟到的 running 不覆盖终态，新 run 不接收旧 run 的记录。真实失败保留位置和已发布结果，只有支持的重试/取消才有可操作入口。

没有真实总量就不显示百分比。长等待保留最后已知动作、实际耗时与连接提示，不轮播新文案。回答 EOF 与已保存分开；修订预览就绪与应用完成分开。终态与取消确认停止所有执行循环。

## 6. 动效与无障碍

复用项目 breathe 与 press/feedback/panel token，呼吸只用于当前节点或小状态点。记录进入用 opacity/transform，正文和输入框保持稳定，避免大面积发光、不断重绘骨架或全文位移。

`prefers-reduced-motion` 下关闭呼吸和位移，保留静态图标、文字与状态颜色。过程收起或页面不可见时不运行无意义动画，模拟执行状态仍独立保存。aria-live 仅播报新活动和重要状态，不每秒播报计时、每个 token 或每条内部日志。展开/收起可打断，键盘触发直接切换。

## 7. 必须可操作的演示与验收

| 演示 | 验收效果 |
|---|---|
| 导入并生成 | 链接/关注点一次提交后开始模拟处理，不要求逐一启动转写/索引 |
| 摘要活动 | 行随执行逐条出现；文字先可读，补图继续；纯文字分支无截图活动；失败重试可重放 |
| 问答活动 | 依据问题/引用走不同实际模拟分支；回答流式输出时过程可见并继续更新，旧消息和草稿保留 |
| 修订活动 | 根据要求/范围产生活动；没有取证则不显示取证；完成后预览、应用、撤销，待应用停止循环 |
| 事件归并 | 重复、乱序/游标缺口、迟到 running、旧 run/attempt 不产生重复或倒退；断线恢复按已知事件继续 |
| 过程卡 | 当前/最近记录紧凑，完整记录可展开；无预设未来步骤、无空等时假活动，用户折叠不被覆盖 |
| 阅读与回查 | 导图展开/放大、节点定位、截图放大、时间改变模拟播放器位置 |
| 专注模式 | 阅读/问答放大和恢复；滚动、草稿、引用、时间与在途输出不丢、不重发 |
| 选段/截图提问 | 文本或截图形成独立引用卡，问题单独输入，可移除/回到原段，选择不自动发送 |
| 标签筛选 | 常用与已选标签可见，全部标签可搜索/多选；筛选后计数与卡片一致 |
| 桌面与动效 | 1440px/1024px 无横向溢出，输入框可见；减少动态效果仍能理解所有状态 |

示例可沿用现有 PgBouncer 视频 fixture，摘要文字、图注、章节、回放时间、导图与标签对应同一版本。素材不冒充真实视频画面。浏览器实际点击入口并检查控制台；交付可重放入口与关键状态截图。浏览器未验证的异常场景单独列待验，脚本归并检查与浏览器验收分别报告。
