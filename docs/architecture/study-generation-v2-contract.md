# Study generation recipe v2

This document describes persisted `study-v2` runs. New generation requests use `study-v3` (see `study-generation-v3-contract.md`). Recovery reads the saved recipe: a `study-v1` run continues its original segment checkpoints and sequential assembly, and a `study-v2` run retains the contract below. A recipe mismatch fails as `unsupported_checkpoint`.

The source manifest freezes raw transcript, OCR, and Vision observations and their evidence IDs. V2 derives a bounded term evidence aid with visual spellings, source IDs, nearby ASR mentions, and possible conflicts. At most 16 candidates and 12 visual excerpts enter each prompt; omitted counts are explicit. It does not mutate the observations or authorize a global string replacement. Segment and automatic title prompts use the same derivation and instruct the model to distinguish uncertain or competing names. Automatic video title writing uses a blank-title database condition and records `title_origin=auto`; user edits record `title_origin=user`. Nonempty legacy titles have unknown origin and are left alone.

V2 retains segment generation and adds one global organization call. The global model returns a `groups` plan with every old block ID exactly once and a title chosen from one member. The server assembles the final body from validated old blocks. Each final block includes `source_block_ids` (for example `"source_block_ids":["s1-plugin","s2-plugin"]`), the original content, and the union of evidence IDs and relations. A block with a `contradicts` reference cannot be merged. Missing or repeated IDs, invalid references, excessive input, or a failed model call fail the run; no partial version is published. V2 does not silently truncate the global input: at most 120 blocks and 96 KiB of serialized blocks enter that call, otherwise the run returns `source_limit_exceeded`.

The global call has its own `study-v2.global.*` checkpoint, prompt digest, token reservation, usage settlement, retry bound, and worker cancellation/lease checks. Segment calls use `study-v2.segment.*`; V1 keeps `study-v1.segment.*`. The completed run's `usage` includes the added call and its actual or estimated tokens. Generated bodies retain `generated_needs_review` and observation coverage warnings. A changed source hash, cancel request, lease loss, or conflicting human edit prevents replacing the current edited version; a completed regeneration may remain a candidate for review.
