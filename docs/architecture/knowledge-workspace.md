# 知识库研究工作区

## 实施范围与验收

本次建设围绕三个相连的用户流程：跨视频研究、检索诊断、可治理的长期记忆。

1. 集合检索：在授权成员集合上统一计算 BM25 语料统计，与向量召回进行 RRF 融合；保留视频、模态、时间与来源标识。测试空集合、跨用户隔离、跨视频同序号片段和精确术语召回。
2. 知识库 Agent：复用有界执行循环，检索工具可覆盖集合或指定成员，窗口工具必须选择视频；每次模型/工具边界与恢复时重新验证成员范围。成员变化后停止旧运行，避免旧观察回流。既有历史保持展示用途。
3. 产品工作区：知识库内提供问答与研究入口、按视频分组的证据、调查轨迹与回放入口；加载、空结果、取消、失败和预算耗尽均展示真实状态。
4. 检索测试台：使用原始问题调用真实检索管线，支持向量、关键词、混合模式，展示各通道、融合候选、最终排序、降级与耗时；不调用最终答案模型，不自动保存用户测试问题。
5. 运行详情：读取 owner-scoped 执行记录，展示状态、步骤、耗时、预算与用量来源；不返回私密规划草稿、密钥、完整内部检查点。
6. 长期记忆：用 PostgreSQL 持久任务替代进程内交付保证，任务与消息事务关联、幂等处理、租约恢复、有限重试；写入前继续检查有效授权。沿用偏好抽取边界、撤回/删除与最小历史身份快照。

## 界面方向

面向桌面 Web，延续映知现有视觉语言，采用资料研究工作台：来源视频是可辨识的资料卡片，证据以时间片段呈现，研究过程使用真实事件驱动的时间轴。工程诊断放在独立测试台和可展开运行详情中；日常问答优先展示发现、依据与下一步。

## 验证

已添加权限、跨视频证据、成员变更、记忆任务重试与撤回行为测试。正式源码目录的 Go 测试、vet、四个命令入口构建、相关并发检测，以及前端 33 项测试、typecheck 和生产构建通过。仓库根目录的全量测试与 vet 会同时扫描被忽略的本地 Go 草稿；若草稿存在重复入口，应与正式源码检查结果分开记录。

桌面浏览器使用接口夹具验证研究发送、流事件、来源高亮、运行详情、会话记忆策略、检索结果与带时间戳的回放链接。夹具验证界面交互，不代表真实模型质量评测。

## 运行边界

服务端重启时通过模型迁移创建记忆任务表；记忆仍受服务端 `memory.enabled` 和用户、会话有效策略控制。自动抽取沿用明确回答偏好的规则，不把视频内容当作个人记忆。知识库历史消息仍仅用于展示，不直接作为后续研究的事实依据。

真实模型质量与大规模集合延迟需使用本地私有评测数据另外衡量，报告不进入 Git。目前 BM25 在授权集合上计算语料统计，大规模集合吞吐尚未验证。
