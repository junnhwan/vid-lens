# 连续转写与逐句回放

## 问题与目标

实际视频的重叠 ASR 窗口独立返回文字。全文进行字符串去重，时间轴直接展示原始窗口，检索又重建全文：同一语音在三个路径中具有不同文本边界。固定音频窗口也不是句子边界；仅有 `text` 的服务不能提供句子时间。

本次验收目标是：可读文本无窗口造成的重复，跨窗口句子连贯，全文、时间轴、检索使用同一个确定性装配器；每句原文可回溯到识别窗口，逐句回放时间来自 ASR 或真实音文对齐结果。

## 数据与装配规则

1. 原始 ASR 窗口和服务返回文字保持不可变；音文对齐只附加时间、原文字符范围和方法，不让语言模型改写转写。
2. 优先使用带原文字符位置的词级时间。相邻窗口在重叠原文中寻找同一个语音发生位置，选择靠近 core 接缝的共同词尾，一次确定左右两边的保留范围；不能分别按固定时刻切词，否则量化时间的差异可能漏字或重复。找不到可信共同接点时使用 core 时间归属。文字的时间不能按字数、字符位置或语速比例估算。
3. 没有词级时间时，只有相邻且实际音频重叠的窗口可以执行保守文字拼接。空窗口、缺失窗口、版本变化和时间间隙必须阻断去重，合法重复说话保留。
4. 统一的装配结果包含连续文字及逐段的原始来源；时间轴、检索和学习文档从它派生。持久化词级时间，在来源投影中按标点与实际停顿合并成句，避免逐字来源使阅读和学习上下文割裂。跨窗口的句子保留两边来源，页面合成完整读句，其播放范围为实际来源范围的并集；读段边界不创造时间。
5. 原文位置必须逐字验证。对齐结果缺词、越界、逆序或与原文不符时，不能标为精确；已发布的转写不能因一次失败而被替换。
6. 时间、连续全文与索引失效在同一事务中发布，并受任务租约约束。对齐任务模式保存在 `task_jobs`，重试沿用模式；新的 ASR 请求显式重置模式。旧 ASR 文字没有因对齐而被修正，错字和错标点仍属于识别质量问题。

## 精度提升

保留当前纯文本 ASR，在识别成功后增加可配置的音文对齐命令。命令接收本地音频与原始窗口文字，返回带字符位置的词级时间。现有完成窗口可以补对齐，不重复支付识别请求；新增任务沿用同一流程。

参考实现采用 Qwen3-ForcedAligner。Apple Silicon 使用 MLX 实现；其他机器使用官方 Qwen 实现，模型和依赖由独立环境安装。算法兼容两种后端，不把 macOS 推理代码放入 Go 核心路径。

- [官方 Qwen3-ASR / ForcedAligner](https://github.com/QwenLM/Qwen3-ASR)
- [MLX ForcedAligner 使用方式](https://github.com/Blaizzy/mlx-audio/blob/main/mlx_audio/stt/models/qwen3_asr/README.md)
- [当前纯文本语音接口](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post)

对齐模型给出的是推理结果，不是人工标注真值。除结构验证外，必须抽查真实语音；噪声、错误转写、音乐和语言混合可能仍需保留不确定性。

## 实施与兼容

1. 锁定时间轴重复和缺窗误拼接的失败测试。
2. 引入统一装配器，迁移消费端、时间轴和检索；修复跨窗口阅读与来源位置。
3. 验证本地对齐器，再接入可取消、有时限的任务处理和已完成窗口复用。
4. 用现有视频补对齐和重建索引。旧回答与学习文档继续读取其冻结快照；索引版本升级要求新构建。
5. 回归缺窗、静音、重复说话、识别差异、跨句、英文空格、原文位置、所有权与失败重试。

## 验收

`exact` 表示该原文有经校验的语音时间，不能解读为人工标注的零误差时间。可读句子取其实际词范围，时间轴、检索与新学习文档共用句子来源及其稳定标识和哈希；原始词时间留在识别窗口中，旧历史引用继续使用已冻结的快照。索引构建版本为 7，来源映射版本为 `source-map-v5-aligned-sentences`。

- 固定回归用例：时间轴和检索重建文字相同；重叠语音只出现一次；非相邻重复语音仍出现两次。
- 全部精确片段：文字为原始窗口的连续子串，字符范围合法，时间在窗口内且单调；跨窗口可读句子的全部来源保留。
- 真实视频：至少检查开头、中段、末尾及原先有问题的窗口边界；播放一句时能听到该句，并检查前后词没有丢失或重复。
- 无原生时间戳、对齐缺词或失败时：显示实际范围及不确定性，不能把逐句精度写成通过。
- 完整后端测试、前端相关单测、交互测试与构建通过；浏览器验收独立于自动化测试。

本次本地真实数据验证使用 24 分 54 秒的视频、75 个重叠窗口。所有窗口完成音文对齐，连续全文为 8,883 字符，来源投影为 299 个句子片段，页面跨窗口合并为 230 个读句；全文与来源重建文字一致。74 个接缝中 71 个找到共同原文与语音接点，其余 3 个按实际 core 时间归属处理。回归覆盖在独立量化时间切分下会丢失“刚”的真实接缝，以及超过 10,000 词时间的长视频学习来源与检索引用映射。浏览器验证回放跳转、完整句子及高亮；未进行人工逐句听音标注，因此不声明零误差或具体误差上限。

## 本地运行

独立安装对齐依赖和模型，不改变 Go 服务的依赖环境：

```sh
uv venv .local/alignment/venv --python 3.12
uv pip install --python .local/alignment/venv/bin/python -r tools/requirements-alignment.txt
```

Apple Silicon 已验证 `mlx-audio==0.5.7` 与 `mlx-community/Qwen3-ForcedAligner-0.6B-8bit`，模型约 1.2 GB。本次验证使用模型 revision `0e1a68e91d815300c7c9754b2a7639378b23db15`；部署时应下载固定 revision 到本地目录。Linux / CPU 的官方 Qwen 后端代码未做本机推理验收。

```sh
.local/alignment/venv/bin/python -c 'from huggingface_hub import snapshot_download; snapshot_download("mlx-community/Qwen3-ForcedAligner-0.6B-8bit", revision="0e1a68e91d815300c7c9754b2a7639378b23db15", local_dir=".local/alignment/model")'
```

在 `.env` 设置 JSON 参数数组，然后重启服务：

```dotenv
VIDLENS_TRANSCRIPT_ALIGNER_COMMAND='[".local/alignment/venv/bin/python","tools/transcript_align.py","--model",".local/alignment/model"]'
```

服务以项目根目录为工作目录时可使用相对路径；其他启动目录应使用绝对路径。保留虚拟环境内的 Python 路径，不将其符号链接解析成系统 Python。命令无 shell 展开，不能使用 `~`、管道或环境变量占位符。

命令接收 `{audio_path, ffmpeg, rows}`，输出 `{rows: [{chunk_index, words: [{text, text_start, text_end, start_ms, end_ms, method}]}]}`。时间为视频绝对毫秒，文字范围为原始窗口去除首尾空白后的 Unicode 字符位置，方法为 `forced_alignment`。必须完整覆盖原文中的字母和数字。原始文字不改写；标点没有单独语音时间，随相邻语音保留。

本地模型一次加载处理全部窗口，单个进程同时只运行一个对齐任务，20 分钟超时，随取消或租约失效终止。成功窗口按音频哈希、模型路径、原文和时间范围缓存到 `~/.cache/vidlens-alignment`，缓存目录仅本人可读；更换模型权重时应使用新目录或清除缓存。

新转写自动补对齐。已有且完整记录音频窗口的转写，页面显示“对齐句子时间”，调用 `POST /api/v1/media/transcribe/:id?align=1`，复用已完成的 ASR。没有记录音频窗口的更早数据需要重新识别；未配置命令时保持范围定位，不宣称逐句精度。
