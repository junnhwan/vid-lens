# 检索与回答链路

## 标准问答路径

标准聊天请求按以下顺序执行：

1. 根据会话绑定的视频、视频库范围或知识库确定检索作用域。
2. 规则层提取时间、实体和句式信号并给出 intent；生产入口 `ChatService.classifyIntent` 只调用 `RuleIntentClassifier`，因此每轮问答不会调用 LLM 分类。这是当前的接线状态，不是设计上的禁用：`IntentRouter` 的规则/LLM 级联和 `LLMIntentClassifier` 仍在代码中，只有 `ParseRecentIntents` 被生产路径使用，级联的 `Classify` 没有接进来。查询改写仍由检索配置决定。
3. `ExecutionPolicy` 把意图映射为检索预算和策略，包括是否改写、作用域、候选数量、是否使用关键词检索、融合、相邻片段回填和 rerank。
4. `RetrievalPipeline` 执行查询改写、关键词/向量召回、跨查询 RRF 融合、原文回填、可选重排、多样性选择和连续上下文扩展，输出带稳定 evidence ID 的候选片段。

用户在设置页“可选增强能力”中选择是否启用检索重排；默认关闭，偏好持久化于 `users.rerank_enabled`。`GET/PATCH /api/v1/user/optional-capabilities` 只读取或修改当前认证用户的选择，演示账号不可修改。普通问答、Agent 与检索测试在构建管线前读取偏好；关闭时覆盖部署或 Free API 的重排模式为 `none`，不会创建重排器或发送重排请求，也不会扩大原有检索候选数量。开启后仍遵守意图策略，采用当前 AI 服务与部署提供的模型或规则排序；配置可用性不等同于真实调用验证。
5. LLM 结合视频上下文自然回答；视频事实有依据才引用，一般知识与视频内容区分。

## 事实源和作用域

- `video_chunks` 是检索内容的关系数据事实源，向量后端只是可重建的检索投影。
- 单视频会话只在当前视频范围内检索；知识库按成员检索，视频库按当前用户可见的视频检索。两种集合都保留总成员和当前模型已索引成员的快照；未就绪成员明确标为未搜索。
- 检索、排序和回答生成是分开的职责：召回负责覆盖候选证据，排序负责调整顺序，生成不能自行创造证据。

## 回答与引用

Chat 使用规则信号区分闲聊、整体总结、普通问题与时间定位，不增加每轮必经的 LLM 分类。单视频上下文包含有限摘要/转写和近期对话，普通问题运行一轮检索管线。空命中可以解释一般知识，但不能声称已确认视频事实或编造引用。

检索块供模型理解上下文，可引用证据则拆成独立的原文句子或语音段。Chat 和 Agent 共用候选编号表，回答使用 `[Cn]` 标注支撑具体观点的句子；最终保存只保留有效编号和实际引用的证据，没有有效引用时返回空引用列表。前端将编号呈现为可点击的原文链接。知识库只使用当前授权成员，视频库会话只使用服务端解析出的已建索引集合；两者的历史消息都走集合安全加载路径，模型上下文按对应范围加载。

原文句子使用160字软预算，保留完整句至2000字硬上限，硬截断明确标记。连续展示上下文上限为4000字，前端默认预览600字并提供展开。每个检索块最多提供 48 个句子候选，超长文本按顺序均匀保留头尾；扩展的相邻上下文没有可引用编号。句子与唯一来源文字精确匹配时使用该来源的时间，分散的证据分别回放。纯文字转写只继承真实音频窗口，不按字数比例估算时间。来源中的文字仅用于内部匹配，公开 citation 的 source refs 不重复携带全文。

多个引用句子来自同一视频、同一模态和相同来源时间范围时，前端将其展示为一个来源片段，时间和回放入口只显示一次，Cn及其原文和结论关联保持独立。不同视频、模态、时间范围或时间状态分别显示；未知/无效时间不自动合并。短粗粒度范围标记“约定位”，不能据此承诺句子级时间。阅读拆段仅改变段落排版，不增加来源数量或推算新时间。

生产入口对结论与原文执行模型语义复核，明确区分支持、支持不足、未检查和复核不可用。复核保留句子候选的原文及来源时间，不代替人工验收。保存前重新校验冻结的授权集合和索引可用范围。

## 时间线定位

`timeline_locate` 使用规则层解析“15:00”“第 15 分钟”或显式区间，并只保留与该范围重叠、且 `time_range_status` 为 `exact/coarse` 的候选 chunk。单点按半开区间包含关系匹配，范围按重叠关系匹配；`unknown` 时间状态不会被当作时间命中。向量后端仍是可重建投影，候选命中后由 PostgreSQL `video_chunks` 回填并校验时间、模态和 source refs，再执行时间过滤。

公开 citation 同时返回 `modality`、毫秒范围、时间状态、source mapping 状态和稳定 source refs。`Source` 只表示 vector/keyword/hybrid 召回通道。时间过滤会把候选召回预算临时放大到上限后再筛选，且不执行可能跨越请求范围的 chunk-index 邻接扩展；没有可靠映射时结果可为空并触发现有的受控降级。

## 模态感知融合

关系事实中的证据模态分为 `transcript`、`visual_ocr` 和 `visual_caption`。检索仍先执行查询改写、vector/keyword 召回、RRF、关系回填和 rerank，然后在候选集上执行低成本模态排序：普通内容问题保持 transcript 优先；字幕、图表、幻灯片、颜色、布局和“画面显示什么”等问题提升视觉证据；询问“画面与解说是否一致”时，若候选允许，最终集合至少保留一条 transcript 和一条视觉证据。

模态排序不把 OCR 或 caption 合并进 transcript，也不把 `Source` 改写成模态。每个候选另外保存 `modality_intent`、`modality_score` 和 `modality_rank`，最终 citation 继续携带原始 `modality`、半开时间范围和稳定 source refs。视觉召回失败时 transcript 可继续回答并明确未取得画面证据；transcript 缺失时 visual-only 索引仍可回答字幕、演示和图表类问题；两者冲突时生成器必须分别引用并保留不确定性。

## Agent 路径

`agent` 使用 [唯一自主循环](agent-evolution.md)，按问题调用文本或视觉工具；Chat 保持标准检索与回答链路。

## 知识库混合检索与测试台

集合 BM25 在当前授权成员的所有关系检索块上统一计算文档频率和平均长度，与向量候选使用同一套 RRF、上下文扩展和重排。相同 chunk_index 的不同视频通过 task_id/chunk_id 区分。作用域由服务端解析：知识库成员为空时在会话准备阶段直接报错，检索管线在解析出的 `task_ids` 为空时同样拒绝执行，因此空集合不会扩大为全库查询；覆盖整个视频库只作为显式的 `video_library` 会话范围存在，并按 owner 和当前向量模型限定。向量后端返回范围外证据时，整次检索以越权错误失败。

`POST /api/v1/knowledge-bases/:id/retrieval-test` 接收 question、mode（hybrid/vector/keyword/answer/agent）及 top_k（1–10，默认 5）。接口在查询前后验证成员与索引状态；返回各通道候选、融合结果、最终证据、耗时和降级原因。hybrid/vector/keyword 使用原始查询；answer 使用普通回答的改写、路由与策略，agent 使用研究工具检索策略（不执行 Planner 或最终生成）。保留当前重排配置，不生成最终答案、不创建聊天消息。AI 调用继续进入现有调用治理。前端入口为 `/kb/:id/retrieval`。

当前 BM25 在应用进程中扫描授权语料并计算统计，一轮请求或研究运行复用不可变语料与统计，目标补查保持集合统计口径。同一查询的 embedding 供不同目标复用，向量目标搜索最多两个并发 worker；向量与关键词通道独立执行。单通道故障可保留有效通道并记录失败，但取消、超时与越权证据继续中止；大集合下的延迟和内存开销仍需真实数据压测后决定是否建立持久关键词索引。检索测试台用于诊断，不把候选分数表述为事实可信度。

## 集合问题路由与覆盖

概要按12个成员一批加载，按问题相关性选择最多8个视频地图，不再按前8个ID选择。明确命名的比较目标定向补召回；问题中的比较维度最多3项，查询总数最多6项。选择阶段先保留必要来源，再按来源和维度相关性选择；相同来源/模态的相同正文去重，相同观点的独立来源和相反观点保留。词面覆盖是补查策略，不能作为语义正确率。

全库主题概览分页读取完整可用概要，并对长概要分段聚合，每轮最多处理12页。达到预算、缺概要、聚合失败或成员未就绪时说明部分覆盖。概要与视频地图只用于导航，事实结论必须回到检索原文；未命中不等于视频从未讨论。

## 原文、连续上下文与索引版本

重排先使用原始命中块及视频标题/模态，再扩展同视频、同模态、可靠时间相邻的原文；超过250ms间隙停止，未知时间不扩展，不以全局chunk序号推断连续性。重叠窗口在预算内共享连续上下文，保留各自锚点与source refs。

引用句以160 rune软预算选完整句段，必要时保留更长句；硬截断有省略标志。`anchor_quote`与`display_context`分别表示公开摘录和有界连续上下文，后者提供独立时间状态和来源映射。模型从邻段选原文时继续使用足够宽的来源范围，不能缩造精确时间。前端支持高亮/展开；复制带视频标题与粗粒度或未知时间状态，未知时间不显示虚假的00:00。

索引build version 5保存独立`index_context`（标题与有界概要）和上下文指纹。Embedding使用上下文+原始正文；关系`content`、引用正文和内容指纹保持原文。旧投影显示需重建，标题/概要上下文变化也会要求重建。关系证据回填覆盖向量投影的正文，防止导航文本冒充原话。
