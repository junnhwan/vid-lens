# 压测与故障演练

本文只描述可重复的测试方法，不预填性能结论。所有测试应在本地或隔离环境运行，并记录代码版本、环境、配置、数据规模、负载和原始结果。

## 基本原则

1. 每次只改变一个变量，例如并发数、文件大小或故障组件。
2. 先执行小流量 smoke test，再逐级增加负载。
3. 同时观察 HTTP 错误率、Go 进程资源、PostgreSQL、Redis、RabbitMQ、MinIO 和磁盘。
4. 故障演练使用专门的测试数据，执行前确认数据可恢复。
5. 日志、JSON 结果和访问登记写入 `artifacts/` 或其他本地目录，不提交密钥、密码、Cookie 或完整 DSN。

## 建议场景

- 视频上传、分片续传和重复上传
- 下载、转写、摘要和 RAG 索引的异步任务链路
- RabbitMQ 投递失败、消费者重启和重复消息
- Redis 不可用时的缓存、配额和分片状态行为
- PostgreSQL readiness、连接耗尽和慢查询
- MinIO 不可用、对象清理重试和向量投影重建
- AI Provider 超时、限流、重试预算和降级链
