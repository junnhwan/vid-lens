### 一、上传与 AI 配置（#1–6）

#### 1. 上传后视频库没有马上显示新视频

- **状态（2026-09-24）：代码已改，待本人验收。** 上传成功后应用外壳通知工作台和视频库重新读取任务列表；多文件逐个完成时逐次刷新。未做页面上传验收。

- **我做了什么：** 一次上传了三个视频。
- **我看到什么：** 上传完成后，视频库没有立即出现这三个视频；手动刷新后才看见。
- **对使用的影响：** 上传结果不够确定，容易让人以为文件没有传上去。
- **建议改进：** 上传成功后自动刷新视频库和工作台列表，或在上传结果中提供明确入口查看新视频。
- **排查线索：** 三个文件的合并请求都成功，但上传后没有马上重新请求视频列表；代码中上传弹窗的成功回调没有接到父页面，列表也只在页面首次打开时加载。

#### 2. 上传成功提示与实际处理状态不一致

- **状态（2026-09-24）：代码已改，待本人验收。** 普通上传明确提示文件已上传、需要进入详情手动开始转写，并提供视频入口；命中完整去重时按返回状态提示复用现有转写和摘要。链接导入仍显示下载任务已创建，避免与普通文件上传混淆。未做页面验收。

- **我看到什么：** 上传弹窗提示任务已创建并进入队列，但当时三个视频只是完成上传，还没有开始转写或生成摘要。
- **对使用的影响：** 用户可能等待自动处理，却不知道还需要到视频详情页手动开始。
- **建议改进：** 上传成功提示只说明“视频已上传”；如果处理需要用户另行启动，应直接写清楚，并给出“开始转写”等下一步操作。
- **排查线索：** 当时视频已入库，但没有对应的处理任务记录或队列消息；视频详情页提供单独启动转写和摘要的操作。

#### 3. 模型服务地址填写方式不清楚

- **状态（2026-09-24）：代码已改，待本人验收。** 表单按能力说明真实拼接规则：对话、ASR、视觉在基础地址后追加各自接口路径，Embedding 直接请求完整地址；示例覆盖硅基流动、OpenAI 和 DeepSeek 对话，说明 DeepSeek 对话主域名也是例外。输入与保存校验会提示已知需 `/v1` 的主域名漏填、重复 `/v1`、将完整接口误填成基础地址、Embedding 缺少 `/embeddings` 等问题。其他服务商仍需核对其能力和 API 前缀；未做真实服务商页面验收。

- **我遇到什么：** 不同服务和软件对地址的要求不一样：有的填主域名，有的要带 `/v1`，有的要求完整接口地址。表单不容易看出当前字段属于哪一种。
- **对使用的影响：** 配置可能因为多填或少填路径而无法调用，用户只能靠试错。
- **建议改进：** 按模型能力说明需要填写“服务基础地址”还是“完整接口地址”，并提供对应服务商的示例；检测到路径重复时给出提示。
- **本次配置的参考填写：** LLM、语音识别和视觉模型使用 SiliconFlow 时，填 `https://api.siliconflow.cn/v1`；Embedding 字段使用完整地址 `https://api.siliconflow.cn/v1/embeddings`。其他服务商应以其接口要求为准。

#### 6. 模型探测结果不明确

- **状态（2026-09-24）：代码已改，待本人验收。** “拉模型”保留为列表接口读取并在表单中持久显示结果说明；另增逐能力的真实小样本探测，按模型列出排队、运行、成功/失败、耗时及安全分类错误，Embedding 显示实际维度并校验已填维度。服务端沿现有能力客户端和准入机制调用，错误响应不返回上游原文或密钥。ASR 静音样本只能确认请求被接受，不能代替真实语音转写质量验收；探测可能产生少量供应商费用，页面先说明。修改相关字段会清除旧结果；未进行真实供应商调用或页面验收。

### 五、长视频摘要

#### 33. 长视频摘要一次性输入完整转写，缺少长度控制与分层总结

- **状态（2026-09-24）：代码已改，待本人验收。** 短转写继续单次摘要；长转写按 ASR 时间窗的合并转写贡献拆分，保留重叠去重后的全部正文。旧任务缺少可用时间窗时按完整转写拆分并标为时间未知。每段和每层合并产物写入 `summary_parts`，输入指纹及模型名决定是否复用；重试从失败段继续。详情显示分段 / 合并进度和失败段，任一段失败或输入超预算时不写入最终摘要，任务仍按既有失败 / 重试机制处理。显式强制重新生成会清除旧最终摘要和旧检查点，避免新任务失败时把旧报告显示为本次成功结果。
- **模型上下文核对：** 本地 AI profile 记录模型为 `qwen3.8-27b`，项目配置和 profile 均未提供该服务实例可用的上下文窗口，不能据模型名推断中转服务的实际限制。实现默认按 8192 token 的保守窗口预留固定提示词、1536 token 输出及安全余量，使用 UTF-8 字节数作为输入 token 上界近似；可通过服务进程环境变量 `VIDLENS_SUMMARY_CONTEXT_TOKENS` 按实际服务限制调整。上游若仍因窗口或输出限制拒绝 / 截断，请求明确失败，不展示为成功摘要。
- **本地数据核对：** 只读查询 `video_transcription_chunks`，三个现存任务分别有 4、5、20 个完成分片；20 片任务的核心时间范围到约 5796 秒，分片正文合计约 108000 字符。这些数据足以触发长文本路径；本轮没有向模型发送实际视频内容。
- **手动验收建议：** 重启后端使自动迁移创建 `summary_parts`，再重启前端。选择长视频生成摘要，核对详情进度从分段进入合并，最终摘要包含片头、片中、片尾信息；中途模拟模型失败后确认任务失败状态、覆盖数和 #18 诊断提示，再恢复服务重试并观察已完成段未重复调用。短视频检查仍为一次摘要请求。验收由本人统一进行。

- **我想确认：** 视频很长时，ASR 转写原文也会很长；如果一次性把全文发给 LLM，是否可能超出模型上下文窗口或因请求过长而超时。
- **代码核对：** ASR 音频处理可以分片，但分片转写文本会合并为一份 `transcription.Content`。`summarizeTask()` 随后将整份文本传入一次 `taskAI.Summarize()`；`CompositeStrategy` 和 `OpenAICompatibleStrategy` 都用一次 Chat Completion 请求处理完整文本。目前没有看到摘要专用的 token 估算 / 输入长度限制、分段摘要或分层合并。Chat HTTP 客户端超时为 5 分钟；任务级可重试失败默认最多重试 3 次，退避为 1 / 5 / 15 分钟，但摘要策略本身没有额外的 provider 内部重试。
- **当前摘要提示词：** 固定写在 `defaultSummarySystemPrompt()` 中，不是用户可编辑配置。要求将视频 ASR 转写整理成客观专业的 Markdown 分析报告；忽略口语废话、重复和明显识别错误；不要开场白或结束语；文本过短或无意义时输出“无法提取有效信息”；报告必须包含“核心摘要、深度洞察、原始内容精选、领域标签”。此外，标题生成是另一个 LLM 调用：最多取转写文本前 1000 个字符，生成不超过 30 个字的中文标题；它与摘要输入长度处理是两回事。
- **风险说明：** 五分钟是本地 HTTP 客户端超时，不代表上游服务或中间网关会等待这么久；第 18 项记录过上游约 60 秒返回 504 的情况。现有实现因此没有保证长转写能在一次调用中成功；实际是否失败取决于转写长度、模型上下文窗口和上游限制。
- **建议改进：** 摘要前估算输入 token 数；超过安全预算时按转写分片边界拆分，逐段生成结构一致的要点 / 时间戳摘要，再做全片合并总结。保存分段结果并显示“第 n / 总数段、合并总结”等阶段，使失败可从未完成段继续；对短视频仍保留一次请求的简洁路径。评估时应同时检查输入 token、输出上限、超时和最终报告质量，避免仅用字符数作为上下文限制。

## 参考项目观察：DOVideo-AI

- **比较范围：** 2026-09-24 对 `/Users/jacob.z/misc/DOVideo-AI` 做了只读代码对照。以下是可借鉴的设计线索，不是 VidLens 已确认的缺陷或照搬清单；代码指针相对 DOVideo-AI 仓库根目录。

### Markdown 渲染与时间戳跳转

- **参考实现：** `client/src/markdown.js:1–20,42–49` 用 `marked` 解析标题、列表、引用、代码和表格；对 Markdown 链接作标签 / 属性过滤，并把 `[分钟:秒]` 转成视频时间跳转链接。
- **VidLens 对照：** `frontend/lib/markdown.ts:19–27,53–126` 是自定义轻量解析器，标题只识别 1–3 级，当前块类型没有表格；这与回答里 `####` 原样显示的情况相符。VidLens 已有自己的引用和时间证据能力，迁移时需要保留这些行为。
- **可借鉴：** 评估采用成熟 Markdown parser / AST，统一摘要、Chat 和 Agent 的渲染，并将引用标记、视频时间戳作为受控扩展；配套使用经过维护的 HTML 安全净化库。DOVideo 的手写标签过滤只适合作为对照，不建议原样复制到产品。

### 长视频按时间分块，并保存分块产物

- **参考实现：** `server/src/main/java/com/example/server/service/VideoChunkingService.java:14–63` 按五分钟时间窗整理视频片段，生成分块摘要、关键词和向量；`LongVideoContextService.java:18–20,40–50,90–104` 在问答中选择相关块，并限制传给 Agent 的文本长度。
- **可借鉴：** 对应第 33 项，可用时间戳分块、分块级中间产物和可续跑进度作为长视频处理基础；生成整片摘要时仍须覆盖所有分块，再做归并。DOVideo 的相关片段检索和固定字符上限是问答上下文策略，不能直接代替全片摘要，也不应把 24,000 字符当作适用于所有模型的 token 预算。
- **不建议照搬：** DOVideo 某分块摘要失败时会静默退回原文前 500 字符（`VideoChunkingService.java:66–78`）；这样会丢弃剩余内容且可能把退化结果误当作正常摘要。VidLens 应显式标记分块失败、允许重试，并在最终摘要中说明覆盖情况。

### 用户可以校正 Agent 的公开计划

- **参考实现：** `client/src/App.vue:375–400` 展示 Planner 任务和执行轨迹，并允许调整计划；`client/src/useAnalysisWorkspace.js:460–519` 支持添加、删除任务后重跑；后端 `AnalysisController.java:157–167`、`AgentCheckpointService.java:178–211` 接收修订并保存版本检查点。
- **VidLens 对照：** `frontend/components/chat/ChatWorkspace.tsx:645–673` 已展示 Agent 执行状态，但当前记录中用户提出的是查看工具 / 规划输入输出详情（第 31 项），还没有确认用户是否需要直接编辑计划。
- **可借鉴：** 可把“调整公开计划后重跑”作为执行透明度的后续交互选项；先验证用户需求、执行预算和历史可复盘方式。编辑范围应是面向用户的计划任务，不扩展为编辑模型内部 reasoning。

### 失败任务记录与受控重放

- **参考实现：** `server/src/main/java/com/example/server/service/FailedAnalysisTaskService.java:59–75,97–146,149–168` 保存根因类型、脱敏错误和尝试次数；人工重放前检查任务有效性与相同任务占用，并保护已发出的消息不被重复提交。
- **VidLens 对照：** VidLens 已保存 task/job 状态、重试次数、`next_retry_at`、耗尽状态和 trace/correlation（例如 `internal/mq/retry.go:157–179`、第 18–19 项）。可重点核对用户如何看见这些信息，以及是否需要对有权限的用户提供“重试已耗尽任务”的安全操作；无需重做已有的持久化重试机制。
- **不建议照搬：** DOVideo 的人工重放接口放在管理员端。VidLens 是否开放重试、开放给谁、是否需要重新计费或重置预算，需按本项目权限与任务幂等策略单独决定。
