# Execution and recovery

`internal/store` owns short PostgreSQL control transactions; `internal/jobs` bridges them to Asynq. `internal/media` prepares versioned sources and owned image files. `internal/investigator` uses Eino model/tool contracts with durable server-directed stages for new articles; frozen earlier executions retain their ChatModelAgent and sequential Enhanced Tools. Runtime defaults and their validation live in `internal/config`; they are defaults, not benchmarks.

## Durable boundaries

- A visitor request and its Outbox entry commit before acceptance. Deterministic Asynq IDs identify a run/delivery generation. An uncertain enqueue is acknowledged only after matching the existing task's type/payload.
- Each claim increments an execution epoch and creates an attempt. Database time, lease ownership, status, deadline and epoch guard all checkpoints, observations and publication. Network calls/FFmpeg run outside control transactions.
- Source identity includes platform/video/P. A snapshot freezes complete-media SHA-256, text identity, real duration, text provenance and acquisition metadata. Complete anonymous sources from the compatible ingestion pipeline can be reused across interpretation models, detail levels and admission settings when their actual duration and media size fit. The new article keeps its own frozen interpretation specification. A retry retains its original snapshot even when newer text exists.
- Saved original text stays in PostgreSQL independently of media availability. Repeated interpretation uses the completed source rather than sending it through ASR again; changing an interpretation model or rotating ASR credentials does not discard saved text. When no compatible completed source exists, fresh acquisition tries usable platform subtitles first. Its ASR fallback requires a fingerprint containing the actual audio input before reusing transcription from other acquisition work; a video-only remote fingerprint or a same-title/same-duration match is insufficient.
- Article files are ready before publication. Article, image pins, run success, eligible request results and the final public event commit together. Canceled requests do not receive later shared results.
- A question has its own run, checkpoint and private observations. Conversation tail/active-turn transitions and request idempotency share transaction ordering.

The current store serializes short control mutations with one PostgreSQL advisory transaction lock. This intentionally keeps join/cancel/publish/pin ordering simple for the bounded single-host workload. It is not a claim of high write throughput. Read projections use repeatable-read snapshots. Public events retain step versions, so cancellation reads the version at its frozen watermark.

## Server-directed generation

New articles use `vidlens-workflow-2026-10-21-v1`. The server supplies original text and real overview pixels, requests one full-video topic plan containing structural metadata, assigns bounded chapter batches, validates the assembled article, gathers independent evidence verdicts, and permits at most one targeted author revision. The outline does not request a second copy of the body facts. Final affected-section review and a separate whole-article check precede publication. Source acquisition, frozen intent, leases, checkpoints and the immutable publication transaction retain their existing boundaries.

Adjacent short subtitle cues can share a transport container, while every cue's original text and stable `tN` alias remain present. Original segment IDs, coarse ASR timestamps and source hashes remain unchanged in PostgreSQL. Writing batches receive original evidence directly. Each paragraph, list item and table row retains its own citations; figure captions receive actual pixels. An optional bounded investigation can select a source range for a concrete question. The server owns the native media-window ceiling and a constant three-frame sampling cost, including questions that span more than one minute. These are discrete samples, not evidence of an unobserved continuous process.

Complete review responses are decoded per unit. Invalid, duplicated, missing and unassessed results never approve a unit; independent legal results remain durable. The reviewer identifies server-assigned units and need not echo long quotations. A single shared format allowance bounds recovery. Per-unit approval binds the original source and pixel identities, model revision, question scope, complete section context, global title and section order. Revising one chapter invalidates that chapter's dependent results; a separate final check binds the complete article and checks coverage, late topics and cross-section conflicts.

Article work is bounded to 20 logical calls and 20 actual submissions; video-only questions on these articles have a three-call ceiling. Phase reservations include truncation and recovery, and unused capacity is not a target. Context and output reservations must fit the frozen model configuration. A complete source that cannot fit fails explicitly rather than being truncated. These are execution limits, not a quality or arbitrary-duration guarantee.

Stage outputs, chapter revisions and legal verdicts survive worker takeover without resetting counters. Bounded stages permit buffered tool arguments to arrive anywhere within the same 300-second response deadline, still clipped by the run's remaining time. A shorter assumption about streaming cadence cannot cancel them early. Image observations use the same `alias` field as delivered pixels, with explicit observation bounds and strict compatibility for saved `frame_alias` records. A provider failure stops that attempt with its original failure identity and recorded sends, leaving explicit recovery available rather than automatically resending the same large input. An owning-session retry may inherit a compatible source, author plan, draft and real observations, but it creates new call accounting and does not inherit another run's approval. New pixel identities cannot replace the images in a frozen call. Video-only answers use complete original evidence and independent review; existing articles and questions that permit external research retain the established interactive evidence adapter.

## Earlier Eino evidence loop

The following describes the frozen adapters retained for earlier executions and compatible legacy draft retries.

Short sources retain their complete usable text in context. New executions handle large transcripts through a chronological index and bounded original-text chunks. Before composing a full article, the Agent must save a derived navigation card for every delivered chunk; an undelivered chunk cannot be marked processed. Cards retain original citation aliases and support planning, while detailed claims and quotations remain grounded in original text. Questions start with relevance-ranked original candidates and can widen the search. Retrieval currently ranks lexical terms, including Chinese word pairs; semantic embeddings are not implemented.

`read_source` accepts chunk IDs, original segment IDs or time ranges, includes chronological neighbors, and supplies a stable continuation offset. Long individual cues are sliced without losing Unicode text, changing the canonical source ID or inventing finer timestamps. Older read bodies become explicit reload references; recent original reads remain available. Source cards, pending delivery and original source identity survive checkpoints and compatible explicit retries. The original transcript remains in PostgreSQL. Source length, cumulative calls, time and per-request budgets still bound processing; this is not an arbitrary-length or quality guarantee.

New source-card executions size each navigation card for the delivered original text, available output and remaining whole-video navigation budget. Rejections return the actual length, current ceiling and a shorter correction target; accepted cards remain immutable. Serialized navigation and space for remaining cards are bounded without truncating original evidence. Earlier executions keep their frozen card limits, while compatible explicit retries retain their saved source coverage.

Sparse overview frames span the whole duration. New executions deliver at most three overview images at a time, retaining undelivered work separately from delivered but unobserved pixels. Recorded images can be unloaded; necessary comparison frames stay protected. Review batches normally use the same small delivery target, but an indivisible comparison retains every required frame. The total working-set limits remain in effect, and incomplete source delivery, observations or review coverage block publication.

New executions assign each semantic review unit exactly once. A unit that cites pixels receives a joint review with all of its cited original passages, speech at the image timestamps, chronological neighbors and actual images; it is not first sent through a text-only pass that cannot finish its visual claims. Pure text units retain text review. Joint findings can cite the original text for a text error or the actual unit's pixels for a visual error. Missing or `not_assessed` results still block publication. The review protocol is frozen independently of authoring, and older runs retain their original modality obligations. Compatible explicit retries keep saved source cards and drafts while selecting the new review contract.

A complete review report can contain both material findings and `not_assessed` units. New executions return both to the author's bounded evidence-acquisition and repair loop, preserving the distinction between a contradiction and unfinished assessment. They do not discard valid findings or approve the gap. The author can reread originals and correct misplaced citations; unchanged submissions cannot refresh its budgets. Publication still requires every final unit to have a supported verdict for the exact current candidate and source identities.

New reviews gather findings across the full text phase before returning one bounded author correction. Once text passes, the same rule applies across visual batches. This avoids spending a whole-document correction for each newly reached chapter. Per-unit evidence bindings distinguish the original passages actually cited from other delivered context: neighboring text can complete a sentence but cannot silently replace a misplaced citation. After a truncated multi-unit response, the reviewer may grow its output once within the frozen configured capacity before splitting; a completed response or split tree remains replayable without new physical submissions. Correction, call, time and publication limits remain enforced.

Review validation in new executions projects out extra null annotations and exact echoes of the server's supplied context before strict decoding. A unit echo must match that unit's identity and original context; mismatched metadata and other nonempty unknown fields remain invalid. The raw model response stays immutable, and accepted projections record which fields were ignored. Required identities, one-result-per-unit coverage, verdicts, readable quotes and delivered evidence retain the same validation, so context normalization cannot turn a contradiction or missing assessment into approval. Earlier executions keep their strict parser.

Author feedback is bounded to 16 affected fields with up to four material findings per field. Multiple findings in one field no longer consume slots intended for other fields. The original review results remain persisted, and all final units must still pass review; this grouping does not increase the correction count or turn omitted feedback into approval. Earlier executions retain their raw 16-finding ceiling.

`find_evidence` locates candidate original segments. `read_source` expands exact text and neighbors. `inspect_video_window` extracts bounded real frames/crops or reloads original references. It returns persisted metadata and actual image parts. An adapter bridge keeps tool calls/results intact and moves tool images into a following multimodal user message for compatible providers. This bridge is covered by transport tests and a real model capability check.

`record_observation` persists visible facts, literal details/units, inferences, conflicts, gaps and question status. New images cannot be evicted before that succeeds. Current comparison groups can remain protected; other recorded images become reference-only messages. Original observation records rebuild evidence capsules. Checkpoints store frame references, complete tool associations and protocol version, never Base64 or private model reasoning. Interrupted pending calls replay through stable operation identities; saved results are reused.

`submit_article_draft` (or `submit_article` for older checkpoints) and `submit_answer` create a candidate, not publication by themselves. The server validates block/map structure, IDs, snapshot ownership, contiguous exact-text citations, actual frame times, observation coverage, image files and stated limitations. Final submission has one bounded correction; new article drafts can repair individual batches before that boundary; independent article/block/citation errors are reported together. Critical unresolved questions block publication. These are mechanical checks; they do not prove the model's interpretation is correct.

For ASR services returning only text, a segment is labeled by its actual audio window. The backend does not fabricate sentence timestamps. Remote submissions and available request IDs/usage are persisted separately from active messages. Unknown external outcomes may be charged twice; no exactly-once provider promise is made.

The first durable completion of each business operation also advances the run's business-progress time in the same fenced transaction. Heartbeats, submissions and replaying completed outputs do not advance that clock. Confirmed resource contention has a separate bounded wait record: only time backed by live resource and parent-run leases is excluded from the stall clock, within the frozen queue limit. Completing or canceling a resource wait does not manufacture business progress; stale records and old execution attempts cannot keep a stalled run alive. ASR updates one persisted activity step after each completed or restored audio window, with processed duration and total duration. Long, productive transcription therefore remains distinguishable from a stalled phase without extending any call or task budget.

Model responses are streamed **inside the worker**, concatenated into complete tool calls/results, then persisted. Public SSE still has no token deltas. A first meaningful response must arrive within 90 seconds; role-only chunks do not satisfy this. Content/tool/reasoning progress has a 60-second idle bound, and the whole call has a 180-second bound. Once the current images have recorded observations and critical questions are supported, an article call can use the 300-second writing allowance. Provider reasoning is discarded before persistence. An interrupted stream or missing finish marker cannot become a completed operation. This avoids confusing a long non-stream generation with a response-header timeout.

## Retries, interruption and restore

Asynq schedules ordinary retries. PostgreSQL retains cumulative failure, operation-submission and active-time budgets plus absolute deadlines. Reconciliation does not create a parallel everyday scheduler: it inspects the current broker task and business lease, repairs a confirmed missing delivery, wakes a completed dependency, or converges an exhausted/archived/deadline state. Unknown Redis state does not mean task absence.

Graceful shutdown stops work cooperatively and preserves the latest checkpoint without granting a fresh budget. An expired old attempt cannot publish after a new claim. Child processes use process groups, bounded waits and cancellation. Each selected model/ASR invocation stays within the worker's bounded call; asynchronous provider jobs and polling are not implemented.

A repeated interpretation whose original text survives an expired video can wait for one shared `source.restore`, then continue on the same snapshot without ASR. Its future article work remains bounded by admission. A valid visual question can also depend on that shared restoration; it releases the Q&A pool slot and retains its own answer identity. The downloaded bytes must match the frozen original-video fingerprint. Restoration reuses old text and never regenerates a published article. A changed source fails honestly. Replacement frames get new IDs; image viewing alone never triggers restoration.

## Resource and asset lifecycle

Separate generation, interactive and maintenance pools preserve a Q&A slot. Download, FFmpeg and ordinary/interactive AI lanes use Redis resource leases with PostgreSQL leases as the final fence. Cache entries are small, collision-checked, expiring indices in a fixed slot set; bytes/media/conversations are not cached in Redis. Capacity is reserved in PostgreSQL before expensive work and checked against real disk availability.

Cleanup marks an unpinned expired frame `deleting` under the same transaction order used for new pins. Original video/audio assets are retained until explicit cleanup; disk pressure never automatically removes them. Physical deletion occurs outside the transaction and can resume from `deleting`. Run/checkpoint pins outlive an attempt; published image pins have article lifetime. Answer/history/diagnostic retention is separate. Orphan cleanup only visits the backend's own `work`/`assets` roots and preserves active runs.

The Go runtime applies a soft heap limit; FFmpeg threads and child RSS are bounded/observed. The Compose file supplies process-group memory limits for a containerized deployment. Resource defaults do not constitute a server capacity or quality benchmark.

Vector retrieval is not enabled. Current-video evidence gathering uses exact temporal/keyword text access alongside full-source coverage. PostgreSQL remains the source of truth; any future vector projection must use pgvector and must not replace the whole-video overview.

## Earlier bounded article drafts and clocks

New article runs use `source-context-v3`: `begin_article` persists a full-video outline, `save_article_sections` writes or replaces 1–3 planned chapters, and `submit_article_draft` submits the current revision. Only validated drafts enter the existing publishable `candidate` operation. Stable `tN`/`fN` citation aliases resolve to owned transcript/frame metadata on the server; final validation still checks the assembled article and actual image observations.

Draft revisions and received/rejected payloads have separate operation kinds in `run_operations`, with execution fencing, replay hashes and revision checks. Completed chapter writes are projected out of later model history; a canonical draft summary and explicit chapter reads preserve repair access without repeating the entire article. A syntax failure records an offset and retries only the current batch. Three identical draft errors stop unproductive attempts. Batches are limited to 64 KiB; stored draft revisions and received candidates to 512 KiB, at most 48 draft revisions, within the existing model-call and task budgets.

Worker recovery continues the same operation identities and budgets. An explicit retry by the owning visitor session creates a distinct run, reusing saved chapters and observed evidence only when source, frozen configuration, protocol and ready media are compatible. Otherwise it starts from available source material. Old requests and published articles remain unchanged. The legacy catch-all final-submission failure is eligible for explicit retry; invalid candidates never become published fallback content.

`MODEL_RESULT_INVALID`, `MODEL_RESULT_NOT_SUBMITTED` and `MODEL_OUTPUT_TRUNCATED` permit explicit retry without silently adding automatic provider submissions. Actual source insufficiency remains distinct. Rejected candidates stay private; public activities expose only safe task descriptions and outcomes.

Request/turn snapshots add `server_now`. The desktop running clock uses this server anchor plus a monotonic browser clock; terminal duration uses server timestamps. Model reporting distinguishes first body bytes from the first nonempty content/tool delta, and includes response start/end timestamps. Persisted records distinguish submission start from response receipt; response latency excludes subsequent tools, validation and persistence. Resource waiting, response receipt, draft saving, validation and publication are distinct activities.

After every planned chapter is saved, the next model request advertises only `submit_article_draft` and forces that function through the Chat Completions tool-choice option. Successful chapter/limitation writes stay closed until final validation reports a concrete problem. A repair records the rejected draft version; accepting a newer revision returns to forced submission, including after worker recovery. Identical revisions cannot extend a run. Limitation-only citation aliases resolve through the same owned catalog as body citations before publication.

## Visible plans and model-call records

Each logical model call has a stable numbered activity; receiving streamed content or changing its current purpose updates that activity without replacing earlier calls. Each physical submission has a separate persisted record, including retries of the same frozen input. The desktop UI reports both counts and retains tools and observation writes as distinct actions. A collapsed history only changes presentation. These records describe execution outcomes, not hidden model reasoning.

The execution plan is projected from accepted observations, open questions, the saved outline, and chapter revisions. It shows the current stage and saved chapters without adding a planning-only model call. Streaming a tool name cannot mark work complete; final publication determines completion. Compatible chapter recovery preserves the draft's harness revision, instructions, source duration, and accepted content.

A provider response with no content and no tool call is an empty transport result even if it reports a stop marker or billed reasoning tokens. It receives only the existing bounded submission retry for that logical operation, using the same frozen input and model; it does not spend a content-repair attempt. Exhausted or unknown submissions remain recorded and can still stop a run. PostgreSQL owns checkpoints and accepted results; Redis remains queue, admission, lease, and rebuildable-cache infrastructure.

Earlier Q&A runs can submit compact `tN` / `fN` aliases, and the server resolves them to owned transcript/frame metadata before the same final citation validation. External-reference and article-passage citations retain their complete validated form. Frozen schemas remain supported; this changes neither the public answer shape nor published article content.
